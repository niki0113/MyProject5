# 視覚メディア研究室の発表スライド（仁木デザイン）

仁木さん用の発表デザインを再現する部品集で、.pptx を生成する。

研究室の先輩の資料（大浦さんの 2026-10-07 大ゼミ）から、わかりやすさを支えている仕組みだけを借りた。
借りたのは、章名の常時表示、矢印から結論の一文への流れ、番号つきの枠、注目する列を色分けした表の四つである。
見た目は独自に組んでいる。
発表の場で先輩の資料と同じに見えないことが前提なので、帯や中央揃えの見出し、黒地のラベル、ベージュの章扉といった大浦さんの資料の外見は使わない。
配色は仁木さん自身の 2026-07-28 の資料（青と、決め文の黄色の下線）に合わせた。
松田さんの 2026-06-23 の資料からは番号つきの目次を、仁木さんの資料からは全スライドに読み上げ原稿を書く習慣を引き継いでいる。

一般的なスライドの規則（1 スライド 1 メッセージ、改行位置、文字サイズの下限、現在位置の表示）は `readable-slide-design` と `tsutawaru-design` に従い、.pptx の検証と画像化は `pptx` スキルの手順に従う。

## 手順

1. 発表時間と構成を確かめる。大ゼミのような進捗発表でも、研究の全体（研究背景、関連研究、研究目的、提案手法）を毎回紹介し、今回の進捗は「進捗」の章にだけ置く（下の「構成」を参照）。質疑用の補足はまとめの後ろに置く。
2. 生成スクリプトを書く。`scripts/vml_deck.py` を import し、1 枚ずつ部品を置く。スクリプトは発表資料と同じフォルダに残し、修正は常にスクリプトを直して再生成する（.pptx を直接いじると次の再生成で消える）。
3. 実行して .pptx を作り、`pptx` スキルの `validate.py` と画像化で点検する。`assets/template.pptx` は python-pptx 標準の空のテンプレート（効果の既定を空にしたもの）で、ほかの人の資料には由来しない。
4. 画像化した全スライドを見て、はみ出し、重なり、語の途中の改行、札や表のセル内の折り返しを直す。

```python
import sys; sys.path.insert(0, "<このスキルの scripts>")
from vml_deck import Deck, Box
I = lambda x: int(x * 914400)                  # インチ → EMU
CH = ["研究背景・目的", "実装方針の見直し", "MPM の実装と検証", "今後の計画"]
d = Deck(chapters=CH)
B = Box.BODY                                   # 本文領域（区切り線の下から、下端の表示の上まで）
d.title_slide("知的モデリング 2026 後期大ゼミ（2026/10/28）",
              ["月面ローバーシミュレータ向け", "レゴリス相互作用", "リアルタイムモデルの開発"],
              "S2520110　仁木 祥真", image="title.png", notes="発表原稿")
s = d.content("本日の内容"); d.agenda(s, CH)
d.section(0, notes="まず、…")                    # 章扉（章番号は 0 始まり）
s = d.content("月面走行の再現に必要なもの", chapter=0, notes="…")
y = d.bullets(s, [[("走行の再現には ", {}), ("相互作用", {"color": "blue", "bold": True}), (" が不可欠", {})]])
d.arrow_down(s, B.x + B.w // 2, y + I(0.1))
d.key_message(s, [("DEM では ", {}), ("リアルタイム性", {"color": "key"}), (" を確保しにくい", {})], y=y + I(0.65))
d.save("out.pptx")                             # 保存時に「n / N」を埋める
```

## デザインの要素

キャンバスは標準の 16:9（13.33 × 7.5 インチ）、フォントは BIZ UDPゴシック（Windows 10 以降の標準の UD フォント）。

| 要素 | 書式 | 部品 |
|---|---|---|
| 表紙 | 右上に月を思わせる大きな淡い円。左に行事名の札（青の枠線）、紺の太字のタイトル（32pt、意味の切れ目で 3 行）、氏名、VMLAB のロゴ。右に角丸の研究テーマの画像 | `title_slide` |
| 目次 | 青の 01 02 と紺の項目名。`current` で今の章以外を灰色にする | `agenda` |
| 章扉 | 左に大きな薄青の章番号（150pt）と紺の章名、細い縦線をはさんで右に目次（今の章だけ強調） | `section` |
| 内容スライドの頭 | 左上に青い角丸の章の札（「02  実装方針の見直し」）、その下に左揃えの紺の太字の見出し（30pt）、下に淡い灰色の区切り線 | `content(title, chapter=)` |
| 下端 | 右に「7 / 26」（今の番号は青）、最下部に細い青の線だけ。研究室名や氏名、進み具合のバーは置かない | 自動 |
| 本文 | 22pt、行頭に青い丸。キーワードは濃い青の太字 | `bullets`（2 段目は `{"sub": [...]}` で灰色の小さい文字） |
| 結論の一文 | 淡い青の角丸の面に紺の太字 24pt。最重要語だけに黄色（FFC000）の太い下線。上に灰色の下向きの山形を置いて帰結として示す | `key_message`、`arrow_down` |
| カード | 角丸、白地に淡い灰色の細線。上に丸い番号バッジ（紺、選択中は青）、紺の太字の名前、説明、下に淡い青の札。選択中は青い枠線と淡い地 | `num_cards`（`selected`） |
| 流れ図 | 淡い地の角丸の箱を横に並べ、上辺に青い番号バッジ、あいだに灰色の山形。今の段階は青い地に白文字 | `flow`（`selected`） |
| 表 | 見出し行は紺の地に白の太字。行のあいだに細線だけ。注目する列は淡い青の地で濃い青の太字 | `table`（`highlight_col`、`bold_rows`） |
| 画像 | 角丸。説明は下に灰色の小さい文字 | `image`（画像が無ければ破線の差し込み枠） |
| 札 | 角丸のラベル（淡い青の地に濃い青の太字。強調時は青の地に白） | `pill` |
| 注、参考文献 | 下端の表示のすぐ上に 11pt の灰色 | `references` |

色の役割：青 4E95D9（章の札、行頭の丸、バッジ、下端の線）、紺 1F3A5F（見出し、表の見出し行、バッジ）、濃い青 215F9A（キーワード、強調語）、淡い青 DCEAF7（結論の面、札、注目する列）、ごく淡い青 F3F8FD（流れ図の箱、表紙の円）、黄色 FFC000（結論の最重要語の下線。1 枚に 1 か所）、灰色（補足、山形、下端の文字）。
青は仁木さんの 7/28 の資料の罫線と同じ色（テーマの tx2 を明るくした色）。

## 構成

研究室の発表は、進捗報告であっても研究の全体を聞き手に紹介する形をとる。
全スライドを今回の進捗で埋めず、次の章立てにする。

1. 研究背景（研究の動機、対象、なぜ必要か）
2. 関連研究（先行研究と、その課題）
3. 研究目的
4. 提案手法（手法の全体像と、使う理論や技術）
5. 進捗（「進捗の全体像」の表で、前回までに完了した項目、今回進めた項目、未着手の項目を示し、そのあとに前回までの振り返りを 1 枚、今回の進捗を数枚。今回の進捗のスライドは見出しを「今回の進捗：〜」で始める）
6. 今後の計画（スケジュールを含む）

最後に本発表のまとめ（課題、提案、進捗、今後）を置き、質疑用の補足はその後ろに置く。
各章の頭に章扉を入れ、目次はこの六つの章にする。
過去の発表資料に使った図（研究の対象の写真、先行研究の図、手法の図、過去の画面）は、出典を付けて再利用してよい。

## 発表原稿（ノート）

全スライドのノートに読み上げ原稿を書く。

- です、ます調で、そのまま読める文にする。スライドの文（体言止め）を話し言葉に開いて説明する。
- 1 枚あたり 3〜6 文。記号は読み方で書く（「Δt」は「時間刻み」、「φ」は「内部摩擦角 φ」）。
- 章扉は「まず、〜を説明します。」の 1 文。最後のまとめは「以上です。ありがとうございました。」で終える。

## 内容の書き方

- 見出しは、そのスライドが扱う対象を指す名詞句にする。結論は見出しではなく結論の一文に置く。
- 1 枚の流れは「事実（箇条書きや表）→ 山形 → 結論の一文」を基本にする。結論の一文は 1 枚に 1 つまで。
- 研究の数値（理論値、設定値、検証結果）は、手元の資料（引き継ぎ資料など）にある値だけを使う。資料に無い数値や、行事名（何回目の大ゼミか、クラスタ名）が必要なら、ユーザーに聞くか、完成報告で確認を頼む。
- 資料から読み取って書いた解釈（方針変更の理由など）は、完成後にユーザーへ「確認してほしい箇所」として伝える。
- 前回の発表の続きなら、背景は 1〜2 枚に圧縮し、前回からの変更点と進捗を中心にする。
- 画像（UE のスクショ、動画）が手元に無いときは `image()` の差し込み枠を置き、どこに何を入れるかを完成報告に列挙する。

## 部品を使うときの注意

- 改行位置は呼び出し側で決める。`text`、`bullets`、`num_cards`、`flow` には行ごとのリストを渡し、自動の折り返しに頼らない。
- 札、バッジ、表のセル、結論の面は折り返すと崩れて見える。画像化して 1 行に収まっているかを確かめ、収まらなければ語を短くするか幅を変える。
- 本文の下限は 18pt（カード内の説明、表、図のラベル）。下端の表示と参考文献だけ 11pt でよい。
- LibreOffice での画像化では BIZ UDPゴシックが代替フォントで描かれ、実機より字幅が広く出ることがある。画像化で収まっていれば実機でも収まる。
- run の書式は `(文字列, {"bold": True, "color": "blue" | "key" | RGBColor, "size": pt, "sup": True})` のリストで指定する。`"key"` は結論の最重要語（太字と黄色の太い下線）。
